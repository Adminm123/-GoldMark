# GoldMark V2 — แผนทดสอบการใช้งานและปุ่มทั้งหมด
เวอร์ชันเอกสาร: 1.0
Branch: rebuild-v2-2026-10
สถานะ: Test plan — ยังไม่ใช่ผลการทดสอบผ่าน

## ขอบเขตและข้อควรระวัง
- ทดสอบบนระบบ Preview/DEMO เท่านั้น ห้ามใช้ข้อมูลลูกค้าจริงหรือราคาซื้อขายจริง
- ห้ามแก้สูตรคำนวณเดิมระหว่างการทดสอบ UI
- หน้า V2 ปัจจุบันเก็บประวัติใน state ของหน้าเว็บเท่านั้น ไม่ใช่ฐานข้อมูลถาวร
- การตรวจ HTTP 200 หรือ Vercel READY ไม่ถือว่าเป็นการทดสอบการกดปุ่มหรือการคำนวณผ่าน

## ลำดับการใช้งานที่ต้องการ
1. เลือกประเภทธุรกรรม
2. เลือกชนิดทอง/รายละเอียดรายการ
3. กรอกน้ำหนักและข้อมูลเฉพาะธุรกรรม
4. ตรวจสอบรายการที่เพิ่มและแก้ไข/ลบได้
5. ตรวจสอบผลคำนวณและรายละเอียดทุกบรรทัด
6. แสดงหน้าลูกค้า (เฉพาะกรณีที่รองรับ)
7. ลูกค้ายืนยันหรือยกเลิก
8. บันทึก/พิมพ์ตามสิทธิ์และเงื่อนไขที่กำหนด

ทุกขั้นต้องมีชื่อขั้นตอน, คำแนะนำ, ปุ่มย้อนกลับ, ปุ่มไปต่อที่มี validation, และรักษาข้อมูลเมื่อย้อนกลับ ยกเลิกต้องไม่สร้างรายการซื้อขายหรือใบประเมินที่ยืนยันแล้ว

## รายการทดสอบตามหน้าจอและปุ่ม

### A. เมนูหลัก
- [ ] เปิดหน้าแล้วแสดงเมนูธุรกรรมครบ: ซื้อทองเก่า, ขายทองใหม่, แลกเปลี่ยน, ขายฝาก
- [ ] แตะธุรกรรมแต่ละประเภทแล้วไปขั้นตอนที่ถูกต้อง
- [ ] ปุ่มแท็บประเมินราคา / รายการประเมิน / ตั้งค่าทดลอง ทำงานถูกต้อง
- [ ] ป้ายราคา DEMO ชัดเจน ไม่ทำให้เข้าใจว่าเป็นราคาทองปัจจุบัน

### B. กรอกรายการทอง
- [ ] เลือกทองรูปพรรณและทองคำแท่งแล้วสถานะเลือกถูกต้อง
- [ ] เลือกน้ำหนักทุกตัวเลือก รวมถึง 1 สลึง, 2 สลึง, 3 สลึง, 1, 2, 3, 4, 5, 10 บาท
- [ ] ป้องกันน้ำหนักว่าง, ศูนย์, ติดลบ, ค่าที่ไม่ใช่ตัวเลข
- [ ] น้ำหนักชั่งจริง: เว้นว่างใช้ค่ามาตรฐานตามสูตรเดิม; กรอกค่าบวกจึงยอมรับ; ศูนย์/ติดลบต้องไม่ผ่าน
- [ ] ค่ากำเหน็จและส่วนลดต้องไม่รับค่าติดลบหรือค่าที่ไม่ใช่ตัวเลข
- [ ] เพิ่มรายการแล้วข้อมูลและจำนวนรายการถูกต้อง
- [ ] เพิ่มหลายรายการแล้วรายการก่อนหน้าไม่ถูกเขียนทับ
- [ ] ลบรายการแต่ละแถวแล้วลบเฉพาะรายการที่เลือก
- [ ] กลับไปแก้ไขแล้วค่าที่กรอกก่อนหน้ายังคงอยู่

### C. ผลคำนวณ
- [ ] ซื้อทองเก่า: แสดงน้ำหนักมาตรฐาน, น้ำหนักจริง, น้ำหนักขาด, น้ำหนักที่หัก, น้ำหนักสุทธิ, ส่วนลด และยอดรวม
- [ ] ขายทองใหม่: แสดงราคาทอง, ค่ากำเหน็จ, ส่วนลด และยอดรวม
- [ ] แลกเปลี่ยน: แสดงยอดทองใหม่หักยอดทองเก่า พร้อมทิศทางเงินที่ต้องจ่าย/รับคืนถูกต้อง
- [ ] ขายฝาก: ตรวจเงินต้น, อัตราดอกเบี้ย, ดอกเบี้ย และยอดไถ่ถอนตามระยะเวลาที่ระบุ
- [ ] ทดสอบกรณีจำนวนเงินเป็นศูนย์และค่าขอบเขต
- [ ] เทียบผลลัพธ์กับสูตรเดิมจากชุดข้อมูลอ้างอิงที่ผู้รับผิดชอบอนุมัติ
- [ ] ปุ่มย้อนกลับไม่ทำให้รายการซ้ำหรือข้อมูลหาย
- [ ] ปุ่มเพิ่มรายการกลับไปขั้นกรอกและเพิ่มรายการได้จริง

### D. หน้าลูกค้าและการยืนยัน
- [ ] ปุ่มแสดงผลประเมินลูกค้าทำงานเมื่อมีรายการ
- [ ] หากไม่มีรายการ ต้องแจ้งเตือนและไม่เปิดหน้าว่าง
- [ ] หน้าลูกค้าไม่แสดงปุ่ม/ข้อมูลภายในสำหรับพนักงาน
- [ ] ปุ่มกลับไปแก้ไขปิดหน้าลูกค้าและคงข้อมูลเดิม
- [ ] ปุ่มยกเลิกปิดหน้าลูกค้าและไม่สร้างรายการยืนยัน
- [ ] ปุ่มยืนยันทำงานเพียงครั้งเดียว ป้องกันกดซ้ำ
- [ ] หลังยืนยันแสดงสถานะและข้อมูลใบประเมินถูกต้อง
- [ ] ปุ่มพิมพ์เปิดหน้าพิมพ์และจัดรูปแบบ 80 มม. ตามที่กำหนด
- [ ] ปุ่มกลับหน้าแรกรีเซ็ตเฉพาะรายการที่จบแล้ว ไม่กระทบประวัติที่ควรเก็บ

### E. ตั้งค่าทดลอง
- [ ] แก้ราคาขายและกดบันทึกแล้วแสดงค่าที่แก้
- [ ] แก้ราคารับซื้อและกดบันทึกแล้วแสดงค่าที่แก้
- [ ] แก้เปอร์เซ็นต์ส่วนลดและกดบันทึกแล้วแสดงค่าที่แก้
- [ ] ป้องกันค่าติดลบ/ค่าว่าง/ตัวอักษร
- [ ] แจ้งชัดว่าค่าเป็น DEMO และไม่มีผลต่อราคาจริง

### F. ความปลอดภัยและความทนทาน
- [ ] รีเฟรชหน้าแล้วไม่แสดงข้อมูลตัวอย่างว่าเป็นข้อมูลจริง
- [ ] ปิด/เปิดแท็บใหม่แล้วไม่กล่าวอ้างว่าประวัติยังคงอยู่ หากยังไม่มีฐานข้อมูล
- [ ] ทดสอบหน้าจอมือถือขนาดเล็กและแท็บเล็ต
- [ ] ทดสอบการแตะซ้ำเร็ว ๆ และการกดปุ่มหลายครั้ง
- [ ] ตรวจ console errors และลิงก์/ปุ่มที่ไม่มี event handler
- [ ] ตรวจการเข้าถึงด้วยแป้นพิมพ์, label ของ input, focus state และข้อความแจ้งข้อผิดพลาด

## รูปแบบบันทึกผล
สำหรับทุกกรณีทดสอบ ให้บันทึก:
- Test ID
- อุปกรณ์/เบราว์เซอร์/ขนาดหน้าจอ
- ขั้นตอนและข้อมูลทดสอบ
- ผลที่คาดหวัง
- ผลที่เกิดขึ้นจริง
- สถานะ: PASS / FAIL / BLOCKED / NOT RUN
- ภาพหน้าจอหรือหลักฐาน
- ผู้ทดสอบและวันที่

## เกณฑ์อนุมัติ
- ไม่มีกรณีทดสอบระดับ Critical/High ที่ FAIL หรือ BLOCKED
- ทุกปุ่มที่แสดงบนหน้าจอต้องมีการทดสอบการทำงานจริง
- สูตรคำนวณต้องผ่านชุดทดสอบอ้างอิงที่อนุมัติ
- ทดสอบบนมือถือและแท็บเล็ตเป้าหมาย
- แยก DEMO/PILOT/PRODUCTION ชัดเจน
- ยังห้ามนำไปใช้ซื้อขายจริงจนกว่าจะมีระบบยืนยันตัวตน, ฐานข้อมูลถาวร, audit log ฝั่ง server, สิทธิ์ผู้ใช้ และผ่านการทดสอบความปลอดภัย

## หมายเหตุเรื่องสถานะ
เอกสารนี้เป็นแผนทดสอบที่จัดทำจากการตรวจอ่านซอร์สโค้ด ไม่ใช่หลักฐานว่าทดสอบปุ่มทั้งหมดแล้ว การทดสอบจริงต้องเปิดเว็บในเบราว์เซอร์และบันทึกผลทีละกรณี ห้ามเปลี่ยนสถานะเป็น PASS โดยไม่มีหลักฐาน
